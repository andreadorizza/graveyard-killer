# A free Worker runs in OpenCode, started by the computer's own scheduler

Claude Free has no Claude Code and no scheduled tasks: the pricing page lists Claude Code and "Hand off and schedule tasks" as No on Free (checked 2026-11-16). The Worker is the only part of Graveyard Killer that needs either, since the phone saves through the Library app's share sheet ([ADR-0004](0004-notion-share-sheet-captures.md)) and a Ping can be answered from any chat ([ADR-0003](0003-every-exchange-is-a-chat.md)). So a user with no paid plan runs the Worker in **OpenCode**, on one of its free models that keep no data and train on nothing, and their computer's own scheduler starts it every day. Claude Desktop stays the first route; this one is for users who will not pay.

## Considered Options

- **Codex on ChatGPT Free** ([#3](https://github.com/andreadorizza/graveyard-killer/issues/3)). It reads our skills and has the Notion MCP server, but Free access is "subject to rollout", the Free model's image input is untested, and ChatGPT's terms cover the data. It stays the next route to test.
- **Claude Code through a proxy to free models** (free-claude-code with NVIDIA). It needs an NVIDIA key, which [ADR-0001](0001-no-server-no-api-keys.md) rules out, and claude.ai connectors load only with a claude.ai login, so Notion would be added by hand.
- **Freebuff.** When its model notice says so, Freebuff or the provider may train on what is sent, share it or sell it.
- **OpenCode's other free models.** Beam Free keeps data for 30 days; Big Pickle, Flint 40B, MiMo-V2.6-Flash, Iceman and Inkling may use it to train; the Nemotron models say "do not submit personal or confidential data". MiniMax M3.1 Flash and Hy4 flash keep nothing and read images too, so they come next when a chosen model goes. LongCat 2.5 keeps nothing but is capped at 100 requests a day, fewer than one run may need (Zen docs and `opencode models --verbose`, 2026-11-16).
- **A cron line on every system.** cron skips a run while the computer sleeps. launchd starts a missed job "the next time the computer wakes up" and coalesces several into one (`man launchd.plist`), as Claude Desktop's catch-up run does.
- **The user starts each run by hand.** No scheduler to install, but the Library becomes one more graveyard.

## Consequences

- A prototype on 2026-11-16 ran the Worker in OpenCode 1.19.5 on GLM-5.3-Flash Free against a test Library, with the scheduled prompt and the skills unchanged. It finished an Instagram reel (caption, transcript, on-screen text read from the keyframes), a YouTube video (description, transcript, cover), an article and a shared save, as Worker evals 1, 3, 8 and 9 expect, and numbered its two offers after the open ones. It took 42 minutes and 39 model steps for 4 Entries. Its Ping passed on Notion's upgrade advice when the query allowance ran out, which ping.md forbids.
- The free route is for a Notion Library only. A Drive Library needs Google connectors that only Claude has.
- Setup and every chat run in OpenCode's own interface, its desktop app or its terminal, on the same free model. The user's first message there points the agent at [opencode.md](../../plugin/skills/graveyard-killer/references/opencode.md#install), which downloads the skills into `~/.config/opencode/skills`, adds Notion's MCP server to the global config and signs in with OAuth (`opencode mcp auth notion`). The pointer goes in `~/.config/opencode/AGENTS.md`, which OpenCode reads in every chat. A Claude Free chat, phone included, can still answer a Ping, since connectors are on the free plan.
- OpenCode 2.x (`@opencode/cli`) became what opencode.ai installs on 2026-11-16, while Homebrew still installs 1.19.5. Both read the 1.x config shape (`permission`, `mcp.<name>`), the global `AGENTS.md` and the global skills folder ("Migrate from V1", 2026-11-16), so Graveyard Killer writes the 1.x shape and edits the config file itself, since `opencode mcp add` writes to the project in 2.x and to the global config in 1.x. Only 1.19.5 was tested.
- Setup installs one scheduler job with `scripts/schedule.py`. The job runs `schedule.py run`, which starts `opencode run --auto -m <model> "<the Worker prompt>"` in the run folder, so both versions read its config without `--dir`: a launchd agent with `StartCalendarInterval` on macOS, a Task Scheduler task with "Run task as soon as possible after a scheduled start is missed" (`StartWhenAvailable`) on Windows, and a systemd user timer with `Persistent=true` on Linux. The job runs whether or not an app is open, while the computer is awake.
- `--auto` approves every permission not denied, and a post is untrusted input that could ask the model to read the user's files and send them out. So the job's folder holds an `opencode.json` that denies first and then allows reads only in the skills folder, the run folder and the post script's work folders, the shell only for the skill's own scripts (never a bare `python3`, which would allow `python3 -c`), and web fetch and Notion. OpenCode checks each part of a compound command on its own. A live launchd run on 2026-11-16 finished a YouTube Entry in 14 minutes with none of these rules in its way.
- OpenCode does not substitute `$ARGUMENTS` or `${CLAUDE_SKILL_DIR}` in a skill and ignores `context: fork` and `model:`, so the prototype first looked for `references/worker.md` in the worker skill's own folder. The Worker skill names the main skill's folder in words, and the scheduled job names the model with `-m`.
- The Ping's alert is a desktop notification: OpenCode has no push tool and no Gmail connector, so "Ping by" `push` uses a new `post.py notify` command when the agent has no push tool. "Ping by" keeps its values, so a Library needs no upgrade step. The offers still wait in the Settings, so any chat can answer them.
- Worker evals 1, 3, 9 and 12 passed on DeepSeek V4.1 Flash Free in 7 minutes and on GLM-5.3-Flash Free in 24, with 29 model steps each, so DeepSeek is Setup's first model and GLM its second (`run_evals.py --agent opencode`, 2026-11-16; one run each).
- Free models have a usage limit that no tool reports. On 2026-11-16 DeepSeek answered "Free usage limit reached" for about 7 minutes, and OpenCode 1.19.5 then waited with no output and never exited. So the download budget alone limits a run, as [worker.md](../../plugin/skills/graveyard-killer/references/worker.md) already says for a run with no usage tool, and `schedule.py run` reads OpenCode's error log and stops a model that refuses, or that says nothing for 75 minutes, and hands the run to the second model.
- Free models are "free on OpenCode for a limited time". When the chosen one goes, a run on it fails, and that run's Ping cannot say so. So Setup names a second model, `schedule.py run` retries with it, and when both fail it shows a desktop notification itself.
