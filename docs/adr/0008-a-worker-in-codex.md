# Codex runs the Worker from a ChatGPT scheduled task, in a run folder that fences it

People ask whether Graveyard Killer runs on ChatGPT or Codex ([#3](https://github.com/andreadorizza/graveyard-killer/issues/3)). Codex is now the agent inside the ChatGPT desktop app, on every ChatGPT plan: Free and Go get "GPT-6 Luna at Standard speed in the desktop app, subject to rollout" (pricing page, checked 2026-11-17). Codex reads Agent Skills from `~/.agents/skills`, reaches Notion through its MCP server, views images, and the app runs **Scheduled tasks**. So a Codex user installs the skills there, adds Notion's MCP server, and Setup has the app schedule the Worker, where the user can see each run, change the time or run it now. A post is untrusted input, so the Worker runs in a run folder whose own `.codex` folder fences it: commands may read only the skills and that folder, and reach no network, and only the skill's scripts, called by their full path, run outside the sandbox. But the app runs a scheduled task with the user's default permissions, not the folder's (2026-11-17). So the task runs one command, `schedule.py codex-run`, which runs the Worker with `codex exec` in the run folder, where the fence holds, and prints the Ping for the task's chat to give the user. `scripts/schedule.py codex` writes the folder.

## Considered Options

- **`codex exec` started by the computer's scheduler, as OpenCode's is ([ADR-0007](0007-a-free-worker-in-opencode.md)).** It runs with the app closed and catches up after sleep, but the user would see and change the schedule nowhere. The user chose the app's Scheduled tasks for that.
- **The plugin from our marketplace.** `codex plugin marketplace add` reads `.claude-plugin/marketplace.json`, and the plugin installed and listed its skills (2026-11-17). But it installs into a folder named after the version, `~/.codex/plugins/cache/graveyard-killer/graveyard-killer/<version>`, and the rules that let the scripts out of the sandbox name their full path, so every update would break the scheduled run until Setup ran again.
- **One permission profile for everything, scripts included, with the network on.** Codex's macOS sandbox gives a command no GPU: Parakeet stopped with "No Metal device available", and `osascript` could not show a notification (2026-11-17). The scripts also need Python, the tools in `~/.local/bin` and Homebrew, and the speech models, whose paths differ on every computer.
- **ChatGPT's own Notion connector.** Connectors are listed from Plus up (pricing page, 2026-11-17); Notion's MCP server worked on a Free account.
- **The scheduled task runs the Worker itself.** Simpler, one session per run, and the first app run passed evals 1, 3 and 12. But the task ran with the built-in `:workspace` profile, "your default sandbox settings": every command could read the whole disk, `~/.ssh` and `~/.claude` included, though not reach the network, while the scripts and Codex's web search could. A post could have the run read a file and send it out inside a link. The run folder's profile held in a chat opened there and in `codex exec`, not in the task.
- **The fence as the user's default permissions.** It would fence the task, but every other Codex chat too.

## Consequences

- A prototype on 2026-11-17 ran the Worker with `codex exec` (codex-cli 0.169, bundled with the ChatGPT app 26.1111) on a Free account, on GPT-6 Luna, against a test Library. Four things broke, and each fix is in the run folder:
  - The scripts, called as `scripts/post.py`, ran in the sandbox, which hides Python, and the Ping told the user to install Apple's developer tools. Only a call by full path matches the rules.
  - worker.md passes a link through a heredoc. Codex splits a command into parts and checks each against the rules only when it has no redirection, so a heredoc keeps the whole command in the sandbox. In Codex the scripts take the link as an argument; `post.py notify` now takes its two lines as arguments too.
  - Notion's writes stopped with "MCP tool call requires approval, but approval policy is never". The folder sets `default_tools_approval_mode = "approve"` for Notion.
  - The app's scheduling tool needs the user's approval, which a folder with `approval_policy = "never"` refuses. A scheduled task never asks anyway, so the folder sets no approval policy.
  - `codex exec` checks trust by the folder's real path: a run folder under `/var` on a Mac is `/private/var`, so `schedule.py` trusts the resolved path.
- With these fixes, on GPT-6 Luna at medium effort, Worker evals 1 and 3 passed in 6 minutes, but the Ping offered no Proposal for the recipe (eval 12) and a work folder stayed behind (eval 9). At high effort, evals 1, 3 and 12 passed in 7.5 minutes, the answer "sì, sempre" included; a work folder stayed behind again, from a failed `post.py read` of the article that worker.md says to fetch instead. So the run folder sets high effort, and `post.py read` now removes the work folder of a read that fails, which holds nothing the Worker uses (`run_evals.py --agent codex`, 2026-11-17).
- Codex's web search opened the article's page, as worker.md's web fetch does.
- An app run on 2026-11-17, the task running the Worker itself, finished in 7.5 minutes with the Ping right, but a work folder stayed behind: the app hands the agent a long command's output after a few seconds while it goes on, and the agent started the same Instagram read again. So `codex-run` holds a lock, and the task's prompt says to wait. With the task running `codex-run`, the inner run's settings showed the fence: reads in the skills, `:minimal` and the run folder only, no writes, no network, GPT-6 Luna at high effort.
- The final app run on 2026-11-17, the task at high effort running `codex-run`, passed Worker evals 1, 3, 9 and 12 in 6.5 minutes, the answer "sì, sempre" in the task's chat included. The Worker started the same read twice again, so `codex-run` also removes the work folders a run left once it has ended, and the folder's `AGENTS.md` says to wait on a running script. At medium effort, the task's chat had answered "sì, sempre" by saying the Preference was saved, without writing it, so the task runs at high effort too.
- A security review of the commit found three ways out, now closed (2026-11-17). `post.py read` ran outside the sandbox with any link, so a link could carry what the run read in Notion to another site: it now refuses any link that is not Instagram, TikTok or YouTube, before any tool runs, and gives the tools the post's own link rebuilt from its id, since a link on the platform's host can still redirect elsewhere (YouTube's `/redirect`, `l.instagram.com`); a link with no post id goes as it is only for TikTok's short links and Instagram's `/share/` links. The unattended run had every Notion tool approved: `codex-run` now enables only those a Worker needs (search, fetch, query, create and update pages, data sources and views), and a run asked for `notion-get-users` found it unavailable. And `codex-run` took the programs it starts from a file in the run folder, which a task's default permissions can write: it now finds `codex` and Python itself, keeps its settings in `.codex/`, which those permissions keep read-only, and its rule matches only this run folder. Codex's web search can still open any page, as web fetch can on every route.
- The two-step run costs a second, short session per run, and the user answers the Ping in the task's chat, which has the default permissions: the user is there to see each step. A failed `codex-run` prints why, in the Settings language, and shows a desktop notification, since the task itself does not fail.
- The app runs a scheduled task only while it is running and the computer is on ("Keep the computer on and the app running when a scheduled task needs local files"); the docs say nothing of a missed run. The ChatGPT desktop app runs on macOS and Windows, and on Linux in preview; only macOS is tested.
- On individual plans, Free to Pro, OpenAI may train on Codex chats unless the user turns off "Improve the model for everyone" in *Settings → Data controls*; Business, Enterprise and Edu are not used for training by default (OpenAI Help Center, checked 2026-11-17). The saved posts, the Library and the user's answers reach the model, so Setup tells the user and asks them to turn it off before it starts.
- A Ping is sent as in Claude Desktop. Codex has no push tool, so `push` shows a desktop notification through `post.py notify`, as on OpenCode, and the whole Ping waits in the run's chat under *Scheduled*. "Ping by" keeps its values, so a Library needs no upgrade step.
- On first launch the ChatGPT app offers to import from Claude, and it listed the connectors it found in Claude Code's session files under `~/.claude/projects` (`~/.codex/external_agent_session_imports.json`, 2026-11-17). The run folder's profile cannot read `~/.claude`; the evals runner keeps `~/.claude` out of its runs too.
- Free plan usage limits are not published.
