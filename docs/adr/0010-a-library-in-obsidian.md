# A Library can live in an Obsidian vault, reached from the computer only

Some users keep their notes in Obsidian and want their saves there too ([#14](https://github.com/andreadorizza/graveyard-killer/issues/14)). So Obsidian is the third Library app ([ADR-0005](0005-a-library-in-more-than-one-app.md)). An Obsidian Library is a folder inside the user's vault: one note per Entry in an Entries folder, with its fields as Obsidian properties and its long text as the note's body; a `Settings` note laid out like the Notion Settings page; a "Share here" and an "Already read" note; an Attachments folder for covers; and a Base that shows the Entries as a table and as cards. The pointer holds the folder's absolute path. Agents read and write the vault only through the skill's `scripts/vault.py`, which needs neither a connector nor Obsidian open.

The vault is a folder on the computer, and no Claude chat on the phone can read it. So for an Obsidian Library, Recall, answering a Ping and chat Capture work only in the Claude Desktop Code tab on that computer. This undoes, for these users only, [ADR-0003](0003-every-exchange-is-a-chat.md)'s "answer from any chat" and [ADR-0002](0002-settings-live-in-the-library.md)'s pointer in the phone's Instructions. The Ping email still arrives on the phone.

## Considered Options

- **A vault synced through Google Drive,** so the phone's Drive connector could read it. Obsidian does not officially support Google Drive on an iPhone (its help, checked 2026-11-16), and the connector would see a folder of Markdown files with no way to write YAML safely. Rejected.
- **The agent edits the files itself,** with its own Read and Edit tools. No new code, but a caption holds quotes, colons, `#` and line breaks that the agent must quote by hand in YAML, and one slip breaks the note's properties, as typed values broke Drive's cells ([ADR-0005](0005-a-library-in-more-than-one-app.md)). It also needs file approvals outside the session's folder. Rejected for a script, which the Worker's approved `python3` already runs.
- **The Obsidian CLI** (1.12) reads and sets properties and queries a Base, but needs the Obsidian app running (its help, checked 2026-11-16). The Worker runs whether Obsidian is open or not. Rejected.
- **One new note per share,** in a folder. On an iPhone the Share Sheet's *New note* Location does it in one step. On Android, Obsidian's share menu adds to an existing note in one step, while a new note takes an extra step to create and pick (tested on a Pixel, 2026-11-16). One Share here note works the same on both, since an iPhone Location can also add to a bookmarked note. Rejected.
- **Obsidian's `tags` for Tags, or a list property in the user's language.** A list named "Tag" or "Tags" would take any text, but "Tags" clashes with Obsidian's own `tags`, and the user would get no tag pane. Tags are Obsidian tags, with hyphens for spaces.

## Consequences

- The pointer's link is a path, and a path names an Obsidian Library in library.md's table. It goes in `~/.claude/CLAUDE.md` only: Setup skips the phone's Instructions. Each computer has its own path to the synced vault.
- A share is the text the phone appended to Share here. Obsidian on Android adds each share on a new line, with no blank line between bare links; a reel shared from Instagram can come as its caption, of several paragraphs, and then its link, both indented (tested on a Pixel, 2026-11-16). So `vault.py shares` splits the note the same way every time: a share ends at a line that holds a link, and the lines before it, back to the share before, are its caption. Neither blank lines nor the first link can mark a share's start, since a caption holds blank lines and comes before its link. A caption line with a link of its own splits that caption in two, and a note typed by hand before a share joins that share; no share is ever lost. The Worker files each share and moves its exact lines to Already read, escaped, so a share added meanwhile stays and a caption's hashtags make no tags. A share counts as shared on the day the note last changed, read once per run. When the phone and the computer change the note before they sync, Syncthing, a free sync that Obsidian's help names for Android, merges nothing: it keeps the older version as a `.sync-conflict-` copy, and Obsidian Sync can be set to make a "Conflicted copy" too. A share in that copy would be lost to the Worker, so `vault.py shares` folds every conflict copy back into the note, without the shares already moved to Already read, and moves the copy to `.trash`.
- `vault.py list` filters in the script and refuses an answer the shell would cut, so a large Library is never read in part without notice.
- A text property holds one line (Obsidian's help), so a caption of more than one line keeps its first line in Caption and the whole caption in the body. Text from a post is escaped in the body, so that its `#hashtags` make no tags in the user's vault.
- Every Entry gets a cover, on every platform: the Worker copies the post script's thumbnail into the Attachments folder before it deletes the download, as it uploads it to Notion ([ADR-0009](0009-covers-are-uploaded-images.md)). The Base is the Library's only view: [Add the views](../../plugin/skills/graveyard-killer/references/library-obsidian.md#add-the-views) writes it only when it is missing, since the user may have changed it.
- A note is named after its post, such as `Instagram DQx1abc`, and never renamed, so the links to it in the Settings and in Pings keep working. The Base shows the Title.
- A removed duplicate goes to the vault's `.trash` folder, where Obsidian's own trash keeps deleted files. Obsidian does not list it, so the user restores a note from Finder or File Explorer.
- The Worker runs `vault.py` without asking, and a post's text may try to steer the agent, so the script is no way to write elsewhere: it reads and writes only notes, the Base and images inside an Obsidian vault, outside its `.obsidian` and `.trash` folders, with links followed before the check, and `--out` makes only a new `.jsonl` file in a temporary folder (security review, 2026-11-17).
- A command that writes takes its JSON from a file the agent writes in its scratchpad, never from the command line. Claude Code holds back any shell command whose text has a brace beside a quote, even inside a quoted heredoc, as "expansion obfuscation", and a headless or scheduled run cannot approve it (evals, 2026-11-16). Text from a post can hold anything, so no inline format would be safe.
- Saving from an iPhone and the cards view's `image` key are untested, and Android's share menu is not in Obsidian's help. Setup says so.
- Codex and OpenCode run on the computer too, but neither offers an Obsidian Library ([ADR-0007](0007-a-free-worker-in-opencode.md), [ADR-0008](0008-a-worker-in-codex.md)): their fenced Worker runs read only the skills and the run folder, never a vault elsewhere, and neither was tested with one. Their Setup sends an Obsidian user to Claude.
- The evals add `obsidian.json` and run against a test vault, as Drive's run against a test Sheet.
